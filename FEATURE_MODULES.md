# Feature & Module Configuration Architecture

## Overview

This document defines the runtime contract for presentation feature toggles in [src/lib/modules.ts](src/lib/modules.ts#L25-L152), dynamic administrative entity routing in [src/features/admin/registry.ts](src/features/admin/registry.ts#L21-L29), and domain feature module barrels under [src/features/](src/features).

Presentation feature toggles govern optional guest-facing experiences through six distinct mechanisms—each with explicit runtime boundaries:

1. **Navigation Visibility**: [getNavLinks](src/lib/routes.ts#L69-L82) and [AdminDashboardLayout](src/app/admin/dashboard/layout.tsx#L37-L40) filter out navigation links whose `requiredModule` is disabled. Note that [isProtectedRoute](src/lib/routes.ts#L84-L118) evaluates `roles` only and does **not** enforce `requiredModule`.
2. **Selective Route & Render Protection**: Only routes and components that explicitly call `isFeatureEnabled()` enforce toggle state (see [Route & Endpoint Enforcement Coverage](#route--endpoint-enforcement-coverage) below). Unchecked UI routes, unchecked API handlers, and dynamic admin entity routes remain reachable even when a toggle is `false`.
3. **Persistence Model (`Prisma` `modules` JSON Column)**: The `AppConfig` model in [prisma/schema.prisma](prisma/schema.prisma#L11-L84) persists all 9 module flags in `modules Json @default("{}")` alongside `showCountdown` and `showAddToCalendar`, preserving module state across page refreshes, backup exports/imports, and snapshot version rollbacks.
4. **Feature Dependencies**: `groupGifting` depends on `registry`; [resolveModuleConfig](src/lib/modules.ts#L119-L141) normalizes `groupGifting` to `false` whenever `registry` is `false` without throwing validation errors.
5. **Registry Checkout & Catalog Bounds**: Registry contributions operate in dual-mode checkout (Stripe PaymentIntents when configured, or direct-transfer / claim-only fallback) and enforce a `500`-item catalog query ceiling with progressive client-side pagination.
6. **Core Domain Independence**: Core authentication, middleware session checks, database repositories, audit logging, and domain barrels under [src/features/](src/features) operate independently of presentation toggles.

## Persistence & Schema Validation Contract

### `AppConfig` Persistence & Synchronization (`modules` + Widget Columns)

- **Persisted `modules` JSON Column**: `model AppConfig` in [prisma/schema.prisma](prisma/schema.prisma#L11-L84) defines `modules Json @default("{}")` alongside `features` (the JSON array of homepage content cards managed via `/api/admin/features`), `showCountdown`, and `showAddToCalendar`. The `"{}"` column default ensures existing rows upgrade seamlessly via `npm run migrate:deploy` without manual backfills.
- **Saved & Merged Across Lifecycle Paths**: `toAppConfigDbPayload` ([src/features/content/schemas.ts](src/features/content/schemas.ts)) and `PUT /api/admin/settings` ([src/app/api/admin/settings/route.ts](src/app/api/admin/settings/route.ts)) persist all 9 module flags to PostgreSQL, merging partial `modules` updates atop existing persisted flags. Backup export/import (`src/lib/config.ts`, `src/utils/backupValidation.ts`, `src/app/api/admin/maintenance/import/route.ts`) and snapshot version rollback (`src/app/api/admin/versions/[id]/restore/route.ts`) likewise preserve `modules` alongside `showCountdown` and `showAddToCalendar`.
- **Homepage Widget Synchronization**: Updating `modules.countdown` or `modules.addToCalendar` automatically synchronizes `showCountdown` and `showAddToCalendar` (and vice versa), while `getAppConfig()` hydrates legacy empty `{}` `modules` payloads from `showCountdown` / `showAddToCalendar` before applying `DEFAULT_MODULE_CONFIG` defaults.

### Zod Schema & Non-Throwing Dependency Resolution

Module flags are validated with `ModuleConfigSchema` ([src/lib/modules.ts](src/lib/modules.ts#L87-L97)) and normalized via `resolveModuleConfig` ([src/lib/modules.ts](src/lib/modules.ts#L119-L141)):

```ts
import { z } from 'zod';

export const ModuleConfigSchema = z.object({
  registry: z.boolean().default(true),
  groupGifting: z.boolean().default(true),
  weather: z.boolean().default(true),
  weddingParty: z.boolean().default(true),
  attractions: z.boolean().default(true),
  gallery: z.boolean().default(true),
  countdown: z.boolean().default(true),
  addToCalendar: z.boolean().default(true),
  interactive3D: z.boolean().default(true),
});
```

- **Non-Throwing Normalization**: `resolveModuleConfig(rawModules)` parses JSON strings or objects using `ModuleConfigSchema.safeParse()`. Unknown keys (including legacy `guestPasscode` entries in older snapshots/backups) are stripped cleanly, and malformed JSON or invalid field types fall back to `DEFAULT_MODULE_CONFIG` without throwing exceptions.
- **`groupGifting` Dependency**: `groupGifting` depends on `registry`. Passing `{ registry: false, groupGifting: true }` into `resolveModuleConfig()` is **not** rejected with a validation error; instead, `resolveModuleConfig()` mutates `config.groupGifting = false` in-place before returning the resolved `ModuleConfig`.

## Route & Endpoint Enforcement Coverage

### UI Pages & Layouts

- **Server-Guarded UI Pages (HTTP 404 via `notFound()`)**:
  - `/registry`, `/registry/add-item`, and `/registry/edit-item/[id]` (`registry`)
  - `/weather` (`weather`)
  - `/wedding-party` (`weddingParty`)
  - `/things-to-do` (`attractions`)
  - `/photos` and `/photos/slideshow` (`gallery`)
  - `/heart` (`interactive3D`)
- **Homepage (`/`) Conditional Widgets ([src/components/home/HomePageClient.tsx](src/components/home/HomePageClient.tsx#L218-L299) & [src/components/home/HomePageClient.tsx](src/components/home/HomePageClient.tsx#L380-L426))**:
  - Renders the countdown widget only when `config.showCountdown && isFeatureEnabled('countdown', config.modules)`.
  - Renders the Add-to-Calendar button only when `config.showAddToCalendar && isFeatureEnabled('addToCalendar', config.modules)`.
  - Hides homepage hotel block cards and the `/things-to-do` local guide link when `attractions` is disabled, hides the homepage photo gallery link when `gallery` is disabled, and hides the 3D experience callout when `interactive3D` is disabled.
- **UI Pages Skipping Server-Side `isFeatureEnabled`**:
  - **Admin Dashboard Overview & Subpages**: `/admin/dashboard` renders a decoupled administrative overview (`OnboardingChecklist` + module-aware workflow cards) without querying registry items so core guest invitations, seating, and settings remain accessible when `registry` is disabled, while subpages (`/admin/dashboard/registry`, `/admin/dashboard/wedding-party`, `/admin/dashboard/attractions`, and `/admin/dashboard/media`) do not throw HTTP 404 on direct URL navigation so administrators can still curate underlying records while a guest-facing module is turned off.

### Middleware & Guest Passcode Environment Gatekeeping

- **Environment-Governed Login Gate (Not a Module Toggle)**: Site-wide guest passcode authentication is **not** part of `ModuleConfigSchema` or `FEATURE_METADATA`. Instead, [src/middleware.ts](src/middleware.ts#L91-L105) and `POST /api/guest/login` ([src/app/api/guest/login/route.ts](src/app/api/guest/login/route.ts)) enforce guest login protection strictly via environment configuration (`GUEST_PASSCODE` and `GUEST_SESSION_SECRET`) with zero database queries in Edge middleware. Site Settings (`/admin/dashboard/settings`) displays read-only guidance pointing administrators to those environment variables.

### API Route Handlers (`/api/registry/*`, Weather, Gallery, & Schedule)

- **Weather & Gallery APIs Enforcing `isFeatureEnabled` (HTTP 404)**:
  - `GET /api/weather` checks `weather`.
  - `GET /api/photos`, `POST /api/photos/upload`, `POST /api/guest/photos/upload`, `GET/POST /api/media`, `PUT/DELETE /api/media/[id]`, `GET/POST /api/media/export`, `PATCH /api/admin/photos/[id]`, `GET/PATCH /api/admin/photos/moderation`, and `POST /api/admin/photos/moderation/batch` check `gallery`.
- **Registry APIs Enforcing `isFeatureEnabled('registry')` (HTTP 404 — 7 of 11 handlers)**:
  - `GET /api/registry/items` and `POST /api/registry/items`
  - `GET /api/registry/items/[id]`, `PUT /api/registry/items/[id]`, and `DELETE /api/registry/items/[id]`
  - `POST /api/registry/items/batch`
  - `GET /api/registry/capabilities`
  - `POST /api/registry/contribute`
  - `POST /api/registry/payment-intent`
  - `POST /api/registry/scrape/batch`
- **Shared Auth, Scraping, & Webhook Routes Under `/api/registry/*` Skipping `isFeatureEnabled('registry')` (4 of 11 handlers)**:
  - `POST /api/registry/scrape` (reused by Admin Content Hub photo metadata import)
  - `GET /api/registry/session` and `DELETE /api/registry/session` (global guest invitation session hydration)
  - `GET /api/registry/validate-code` (reused by `/guest/collect` address portal)
  - `POST /api/registry/webhook/stripe` (asynchronous settlement reconciliation for already-created PaymentIntents)
- **Group Gifting Enforcement (HTTP 400 Bad Request, Not HTTP 404)**:
  - When `registry` is enabled (`true`) and `groupGifting` is disabled (`false`), partial or group-gift contributions (`targetItem.isGroupGift || amount < targetItem.price`) throw `new ApiError(400, 'Group gifting is currently disabled.')` (**HTTP 400**) in both [src/features/registry/api/contribute.ts](src/features/registry/api/contribute.ts#L33-L37) and [src/features/registry/api/payment-intent.ts](src/features/registry/api/payment-intent.ts#L39-L43).
- **Schedule ICS Export**:
  - `GET /api/schedule/[id]/ics` skips `isFeatureEnabled('addToCalendar')`.

## Registry Dual-Mode Checkout & Catalog Bounds

### Dual-Mode Checkout (`Stripe` vs. Direct-Transfer / Claim-Only)

Capability negotiation is exposed via `GET /api/registry/capabilities` ([src/features/registry/api/capabilities.ts](src/features/registry/api/capabilities.ts#L8-L20)) backed by `getStripeCapability()` (`isValidStripeSecretKey` and `isValidStripePublishableKey`) in [src/lib/stripe.ts](src/lib/stripe.ts#L16-L64):

- **Stripe Card Checkout Mode (`cardCheckoutEnabled: true`)**:
  - Enabled only when both `STRIPE_SECRET_KEY` (`sk_*` or `rk_*`) and `NEXT_PUBLIC_STRIPE_PUBLISHABLE_KEY` (`pk_*`) are configured with non-placeholder keys.
  - Clients create a PaymentIntent via `POST /api/registry/payment-intent` (which optionally adds a `2.5%` processing fee when `coverFee: true` per `CARD_PROCESSING_FEE_RATE = 0.025`, and returns **HTTP 503** if Stripe keys are absent), confirm card payment with Stripe Elements, record the contribution via `POST /api/registry/contribute` (`paymentIntentId`), and reconcile asynchronous settlement via `POST /api/registry/webhook/stripe` (`STRIPE_WEBHOOK_SECRET`).
- **Direct-Transfer / Claim-Only Fallback (`cardCheckoutEnabled: false`)**:
  - When Stripe keys are omitted or placeholder values, `GET /api/registry/capabilities` returns `{ cardCheckoutEnabled: false, stripePublishableKey: null }`.
  - Guests claim physical gifts directly or submit manual peer-to-peer contributions on `CASH_FUND` / `EXPERIENCE_FUND` items configured with an external `paymentHandle` (Venmo, PayPal, or Zelle) via `POST /api/registry/contribute`. Attempting to contribute to a `CASH_FUND` or `EXPERIENCE_FUND` item without `paymentIntentId` when `paymentHandle` is empty returns **HTTP 400**.

### 500-Item Catalog Ceiling & Progressive Pagination

Registry pagination constants are centralized in [src/utils/registryPagination.ts](src/utils/registryPagination.ts#L6-L9):

- **`REGISTRY_DEFAULT_PAGE_LIMIT = 20`**: Default server page size when `limit` is omitted on `GET /api/registry/items`.
- **`REGISTRY_MAX_CATALOG_LIMIT = 500`**: Hard upper bound enforced in `RegistryRepository.getAllItems` ([src/features/registry/repository.ts](src/features/registry/repository.ts#L25-L43)). The storefront hook `useRegistry` ([src/features/registry/hooks/useRegistry.ts](src/features/registry/hooks/useRegistry.ts#L105-L139)) fetches up to `500` items upfront (`GET /api/registry/items?page=1&limit=500`) to support instant client-side category, search, price, and availability filtering.
- **Progressive Client Reveal (`12` + `8`)**: `useRegistry` initially renders `REGISTRY_INITIAL_VISIBLE_ITEMS = 12` cards and reveals `REGISTRY_LOAD_MORE_INCREMENT = 8` additional items per batch ([src/features/registry/hooks/useRegistry.ts](src/features/registry/hooks/useRegistry.ts#L353-L377)).
- **Deep-Link Fallback**: When a guest opens `/registry?item=<id>` for an item beyond the initial 500-item catalog slice, `useRegistry` fetches `GET /api/registry/items/[id]` directly so the modal still opens cleanly ([src/features/registry/hooks/useRegistry.ts](src/features/registry/hooks/useRegistry.ts#L121-L139)).

## Dynamic Administrative Entity Controller Routes

Administrative CRUD operations for structured domain entities route dynamically through [src/app/api/admin/[entity]/route.ts](src/app/api/admin/[entity]/route.ts#L7-L143), `/api/admin/[entity]/[id]`, and `/api/admin/[entity]/batch`.

- **Plural `ENTITY_KEY` Slugs**: Entity route parameters must match the exact `ENTITY_KEY` static properties registered in `getEntityService` ([src/features/admin/registry.ts](src/features/admin/registry.ts#L21-L29)). Unregistered singular slugs (such as `registry-item`, `seating-table`, `sub-event`, `invitation-code`, or `content`) resolve to `null` and return HTTP 404 (`'Entity not found'`).
- **No `isFeatureEnabled` Guard**: [src/app/api/admin/[entity]/route.ts](src/app/api/admin/[entity]/route.ts#L7-L11) checks `getEntityService(entity)` and admin session authorization (`Admin-only`), skipping `isFeatureEnabled()` so administrators can manage underlying data regardless of presentation toggle state.
